BITCRM 使用说明

面向销售、市场、运营和管理员的完整操作指南。

帮助大家理解每个模块记录什么、模块之间怎样关联，以及一项业务动作应该在哪里完成。

完整中英文说明 · 更新于2026年8月6日

1. 快速开始

BITCRM 把客户全过程连接起来：客户是谁、是否形成机会、我们与客户做了什么、下一步由谁在什么时候完成。

Sales Leads
潜在客户
Pipeline
销售机会
Sales Activities
客户互动
Tasks
下一步行动
Dashboard
管理汇总
最简单的理解：Sales Leads 和 Pipeline 说明“我们在跟谁、是什么机会”；Sales Activities 说明“我们实际与客户做了什么”；Tasks 说明“后面还有什么事情要完成”。

1.1 第一次登录

  • 使用管理员提供的用户名和初始密码登录。
  • 进入右上角用户菜单，尽快修改初始密码。
  • 使用 中文 / EN 切换界面语言，使用说明也会跟随切换。
  • 左侧菜单会根据你的角色和数据权限显示可用模块。

1.2 录入数据前的基本原则

  • 先搜索是否已有同一家公司，避免重复建立 Lead 或 Pipeline。
  • 选择正确的 Owner。Owner 不只是负责人，也会影响数据可见范围。
  • 已经发生的沟通写 Follow-up；未来要做的事情写 Next Steps / To-do。
  • 业务上取消的事项使用 Cancel；只有确实不应继续出现在正常列表时才使用 Delete 归档。

2. Dashboard（管理看板）

Dashboard 用于管理汇总，集中展示 Leads、Pipeline 金额、预测、阶段和 Owner 表现；详细客户资料仍应回到对应模块维护。

2.1 主要指标

指标含义如何使用
Total Leads当前权限和筛选范围内的潜在客户数量。判断销售漏斗顶部是否有足够客户。
Qualified Leads已经确认合格的 Leads 数量。检查有多少 Lead 已具备转为销售机会的条件。
Pipeline #当前可见销售机会数量。需要结合金额和阶段一起分析，不能只看数量。
TCV / Revenue根据 Pipeline 金额和合同信息计算的商业价值。要保证 Pipeline 金额、合同年限和日期填写准确。
Current / Next QTR Revenue按季度展示的收入预测。客户计划变化时要及时更新预计签约和开通日期。

2.2 Pipeline 看板与 Sales by Owner

  • Pipeline Kanban 按阶段展示机会，只有业务阶段确实变化时才移动卡片。
  • Sales by Owner 用于比较不同负责人的 Pipeline 结果。
  • Dashboard 的 Owner 选择可能保存在当前浏览器中，需要查看全部时请使用对应的清除或重置功能。
  • 如果 Dashboard 数字看起来不对，先检查 Pipeline 的状态、金额、合同年限、签约日期、开通日期、Owner 和当前筛选。

3. Sales Leads（潜在客户）

Sales Leads 用来管理还没有形成明确销售机会的客户。Lead 内容应足以让其他同事看懂客户是谁、从哪里来、有什么需求、谁负责以及最近进展。

3.1 新建和维护 Lead

  • 填写公司、联系人、Lead Source、Lead Status、Requirements 和 Owner。
  • 少量字段变化可用 Quick Edit；多个关联字段需要一起检查时使用完整编辑页面。
  • 已经发生的活动写入 Follow-up Notes，并单独选择 Customer Visit、DC Site Visit 或 Remote Engagement。Visit 需要填写实际开始和结束时间，Remote Engagement 使用 Activity Date。
  • 未来要完成的事情写入 Next Steps / To-do，并再次独立选择活动类型（可以与 Follow-up 不同）。Remote Engagement 填到期日；Visit 填预计开始和结束时间，系统按结束日期创建关联 Task。
  • 无论通过手工新增、Excel 导入、Quick Edit 还是完整编辑页面，只要 Lead 保存为 Qualified，系统就会立即创建或关联对应的 Pipeline。

3.2 查找和检查 Leads

  • 可以按 Company、Status、Source、Owner 筛选；需要检查通常隐藏的记录时使用 Show All。
  • 顶部汇总卡片会跟随当前权限和筛选范围变化。
  • Column Settings 只控制显示哪些列，不会删除字段或数据。
  • Follow-up History 是客户沟通的时间线。建议写清结果和下一步，不要只写“已联系客户”。

3.3 导入、导出和归档

  • 批量导入前先下载当前 Import Template，不要修改必填表头。
  • 导入后检查 Owner、状态、来源以及是否产生重复公司；所有导入时已经是 Qualified 的 Lead 都会立即转入 Pipeline。
  • Export 适合离线检查，但不能代替在 CRM 中维护正式数据。
  • Delete 会将 Lead 从正常列表归档并保留审计快照，不是无痕彻底删除。

4. Pipeline（销售机会）

Pipeline 用于管理已经确认的销售机会，包括服务、商业金额、成功概率、预计时间、阶段、支持人员、卡点和跟进历史。

4.1 重要字段

字段组业务用途
Company / Contact / Service说明是哪一个机会，以及客户可能购买什么。
MRC、OTC、合同年限、TCV构成汇总和预测使用的商业价值。
Estimated Signing / Activation决定预计收入归入哪个时间段。
Stage / Level / Win Probability分别表示成熟度、优先级和成功信心，三者应保持逻辑一致。
Owner / Support Team明确主负责人，并赋予支持成员对应机会的访问范围。
Current Stuckpoint说明当前阻碍机会推进的主要问题。
Follow-up History / Comments保留客户反馈、决定和业务上下文。

4.2 日常维护机会

  • 可按 Company、Signing Quarter、Activation Quarter、Stage、Level、Owner 筛选。
  • 需要检查 Deal Lost 或通常隐藏的历史阶段时使用 Show All。
  • 在 Dashboard Kanban 拖动卡片会改变业务阶段，操作前应先确认真实客户情况。
  • 已完成活动写 Follow-up，未来行动写 Next Steps / To-do；两部分分别选择活动类型，可以一项是 Visit、另一项是 Remote Engagement。
  • 日期、金额、概率或卡点发生变化时及时更新，保证 Dashboard 预测有参考价值。
  • 可使用 Import、Export、排序和 Column Settings 进行批量工作和检查。

5. Sales Activities（销售活动）

Sales Activities 是客户互动的执行记录。每条活动都有类型、来源、公司、Owner、日期或时间段、状态，并可能关联一个 Task。

5.1 三种活动类型

类型什么情况下使用时间与完成规则
Customer Visit
客户拜访		销售人员离开办公室，到客户办公室、项目现场、活动地点或其他外部地点拜访。填写开始和结束日期时间；可在 Sales Activities 填写反馈，也可在关联 Task 中填写必填 Completion Notes 完成，两边状态和反馈自动同步。
DC Site Visit
数据中心参观		客户来到我们的 Data Center，进行机房参观、技术交流、安全评估或设施检查。填写接待时间、Data Center 地址、来访人员、目的和预期结果；可从 Sales Activities 或关联 Task 完成，反馈自动同步。
Remote Engagement
远程沟通		邮件、电话、线上会议、即时通讯，以及不需要线下见面的其他客户沟通。使用 Activity Date；已完成沟通可写 Follow-up，未来行动通过 Next Steps / To-do 生成关联 Task。
DC Site Visit 不属于客户拜访：它表示客户来到我们的 Data Center。请写清机房地点和客户来访人员，方便接待、技术、安全和后续工作协同。

5.2 新建销售活动

1
点击 Add Sales Activity，选择三种活动类型之一。
2
选择 Source Type。来源为 Sales Leads 或 Pipeline 时，必须从有权限的搜索结果中选择记录，不能只手工输入公司名。
3
填写活动日期或开始/结束时间、联系人、Purpose / Project、Expected Result 和 Remarks。
4
Customer Visit 和 DC Site Visit 只能在 Sales Activities 创建。Sales Leads 和 Pipeline 的 Follow-up 可以选择已经关联的拜访并完成，不会重复创建；这两个模块中新建的快速活动只允许 Remote Engagement。
5
已完成的 Remote Engagement Follow-up 不创建 Task；新的 Remote Engagement Next Steps / To-do 会创建 Scheduled Sales Activity 和关联 Task。Visit 的完整时间、地址和来访信息统一在 Sales Activities 维护。

5.3 状态和提醒逻辑

显示含义
Scheduled活动已经安排，还没有到需要反馈或处理的时间。
Follow-up RequiredVisit 已经结束但还没有填写反馈，或 Remote To-do 已经到期。
Due TodayRemote To-do 今天到期的详细提醒；在汇总表中计入 Follow-up Required。
OverdueRemote To-do 已超过到期日，或 Visit 结束超过24小时仍未填写反馈；汇总时计入 Follow-up Required。
Completed已经记录实际结果或要求的完成反馈。
Cancelled活动已填写原因并取消，记录仍保留用于追溯。
Visit 规则：Customer Visit 和 DC Site Visit 都会在结束时间到达后立即显示 Follow-up Required；只有结束超过24小时仍未反馈时才显示 Overdue。

5.4 筛选、日历、汇总和列表

  • Type：All、Customer Visit、DC Site Visit、Remote Engagement。
  • Date Range：Remote Engagement 按 Activity Date 筛选；Visit 只要开始/结束时间段与所选范围有任何重叠就会显示，包括跨日活动。
  • Owner：管理员使用一个下拉框，在里面勾选一个或多个 Owner。每次勾选都会自动生效，不需要再点击 Filter；选择 All Owners 会清除具体 Owner。
  • Calendar：绿色表示计划中或已完成，黄色表示需要跟进或今日到期，红色表示逾期，灰色表示取消或历史。蓝色日期圆圈 + 今天只标记当前日期，不覆盖原状态背景；也可选择多个日历日期。
  • Activities by Owner：按 Scheduled、Follow-up Required、Completed、Cancelled 和 Total 汇总。Due Today 与 Overdue 均包含在 Follow-up Required 中。
  • Source Type by Owner：按 Sales Leads、Pipeline、Existing Customer、Event、Other 和 Total 汇总。
  • Activity List：每页20条，翻页时保留当前筛选条件。

5.5 修改、完成、取消和归档

  • 客户更改时间时，可对未完成活动使用 Edit / Reschedule；关联 Task 的日期、Owner、公司和内容会同步更新。
  • Customer Visit 和 DC Site Visit 必须在 Sales Activities 创建，但可以在 Tasks、Sales Activities、Sales Leads 或 Pipeline 中填写必填 Completion Notes 完成。所有入口都会更新原来的 Sales Activity 和关联 Task，Lead/Pipeline 不会重复创建拜访。
  • Remote To-do 在 Tasks 中填写必填 Completion Notes 后完成，Sales Activity 自动同步。“打开 Sales Activity”用于查看完整活动信息，不是完成 Visit 的必经入口。
  • Cancel 会保留活动和取消原因；Delete 会将活动及关联 Task 从正常列表归档。
  • 来源为 Sales Leads 或 Pipeline 时，计划和反馈会写入 Follow-up History，并按关联关系同步到对应 Lead / Pipeline。

6. Tasks（待办任务）

Tasks 是日常执行清单，既包括手工新建任务，也包括 Sales Activities 自动生成的任务。

6.1 分组和操作

  • Overdue：超过业务截止时间仍未完成的工作。
  • In Progress：正在处理且尚未完成或取消的工作。
  • Completed：已经填写 Completion Notes 和完成信息的工作。
  • Cancelled：明确停止执行的工作。
  • 可使用 Owner 筛选聚焦任务；非管理员只能看到自己的 Tasks。
  • 完成时必须填写 Completion Notes，让其他人知道实际结果。
  • 只有确实需要继续工作时才 Reopen 已完成或已取消任务。

6.2 关联 Task 的处理规则

Task 来源应该在哪里完成或修改
手工 Task直接在 Tasks 中管理。
Remote Engagement — Next Steps / To-do可在 Tasks 或 Sales Activities 中填写 Completion Notes 完成，两边自动同步。
Customer Visit 或 DC Site Visit必须在 Sales Activities 创建；可从 Tasks、Sales Activities、Sales Leads 或 Pipeline 完成，所有入口更新同一条 Activity 和 Task。
与 Sales Activity 关联的 Task 不能被单独修改或删除到破坏关联关系。完成可以从 Tasks 或 Sales Activities 操作；改期、修改活动资料或取消时，请回到 Sales Activities。
历史数据兼容：上线前没有活动类型或 Sales Activity 关联的旧 Follow-up / Task 保持原样，不会被猜测、回填或强制显示到 Sales Activities。只有新保存且明确选择类型的数据进入同步逻辑。

7. Admin / User Management（用户管理）

用户管理仅管理员可用，用于管理登录账号、角色、启用状态和密码重置。

  • 新建用户时填写唯一用户名、需要时填写邮箱、选择角色并设置初始密码。
  • 按照真实工作职责选择角色，不要只是为了绕过数据权限而赋予 Admin。
  • 人员不再使用系统时可以停用账号，历史 Owner 和业务记录仍会保留。
  • 用户无法登录时可由管理员 Reset Password，并要求用户登录后修改临时密码。
  • 不要为了报表好看而删除或替换历史 Owner；保留真实负责人有助于审计和责任追踪。

8. Login Logs 与 Operation Archive（登录日志和操作归档）

该区域仅管理员可用，用于追踪访问和重要操作。它是审计页面，不是修改客户业务数据的页面。

  • 可按 Keyword、Action Type、Username、Start Date、End Date 筛选。
  • 常见记录包括登录、新建、修改、跟进、完成、取消和归档/删除。
  • 需要确认“谁在什么时候改了什么”时先查日志，再回到来源模块核对当前业务记录。
  • 归档快照可以帮助调查已删除记录，同时保持日常列表整洁。

9. 通用功能

功能正确使用方式
中文 / EN切换界面和使用说明语言，不会自动翻译用户录入的客户内容。
Filters / Clear Filters筛选用于缩小当前范围；Clear Filters 返回模块默认视图。
Owner 多选选择一个或多个负责人；Sales Activities 的复选下拉框勾选后立即生效。
Column Settings只控制显示或隐藏列，不会删除字段。
Import Template / Import使用最新模板、保持表头不变，并在导入后检查结果。
Export生成离线检查文件，正式数据仍应继续在 CRM 中维护。
Change Password使用个人私密密码，并及时修改临时密码。
Cancel 与 DeleteCancel 记录业务取消；Delete 将错误或不需要的记录从正常列表归档。

10. 推荐的端到端业务流程

1
新建或导入 Sales Lead，确认来源、Owner、联系人和需求。
2
每次电话、邮件或线上会议结束后记录 Remote Engagement Follow-up；需要未来行动时增加有日期的 Remote Engagement Next Steps / To-do。
3
Lead 合格后维护 Pipeline 的金额、阶段、概率、预计时间和卡点。
4
我们去客户现场使用 Customer Visit；客户来我们的 Data Center 使用 DC Site Visit；邮件、电话和线上会议使用 Remote Engagement。
5
Task 完成时填写真实结果，Visit 结束后及时填写反馈，保证 Follow-up History 连续。
6
定期检查 Dashboard、Activities by Owner、Overdue 工作和 Pipeline Stuckpoint。
好的记录示例：“客户安全团队已确认 DC 接入方案；8月7日前发送修订报价，负责人 Alex。”这句话包含结果、下一步、截止时间和责任人。

12. 常见问题

三种活动类型应该怎么选？我方人员离开办公室去客户或项目现场，选择 Customer Visit；客户来到我们的 Data Center，选择 DC Site Visit；不需要线下见面的邮件、电话或线上会议，选择 Remote Engagement。
客户临时更改了预约时间怎么办？打开未完成活动，使用 Edit / Reschedule 修改；关联 Task 会同步更新。
为什么 Due Today 和 Overdue 也算在 Follow-up Required 里面？它们是“需要跟进”这个业务状态下更具体的时间提醒。汇总表只在 Follow-up Required 中统计一次，Activity List 仍显示精确提醒。
Visit 应该在哪里创建和完成？Customer Visit 和 DC Site Visit 必须在 Sales Activities 创建，保证时间、地址和来访信息完整。已经创建的 Visit 可以从 Tasks、Sales Activities、Sales Leads 或 Pipeline 完成，原 Activity 和 Task 会保持同步。
为什么 Activities by Owner 只看到自己一行？非管理员只能查看自己的 Sales Activities 和 Tasks；管理员可以查看全部 Owner。
跨日 Visit 会不会被 Date Range 漏掉？不会。只要 Visit 时间段与所选日期范围有任何重叠，就会被筛选出来。
为什么筛选以后汇总数字变了？列表、汇总表和很多 Dashboard 指标都会跟随当前权限及筛选范围。比较全部数据前请先 Clear Filters。
客户会议取消了，要不要删除？通常不要删除。应使用 Cancel 并填写原因，让业务历史可以理解；只有确实需要从日常使用中归档时才 Delete。
