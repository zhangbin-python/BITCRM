BITCRM 使用说明

以 Sales Activities（销售活动）为中心，帮助团队把客户沟通、拜访、后续任务和业务记录连成一个闭环。

更新：2026年8月 · 中文版

1. 先理解整体流程

BITCRM 不只是保存客户名单。更重要的是记录“客户从哪里来、我们做了什么、下一步由谁在什么时候完成”。

Sales Leads
潜在客户
Pipeline
销售机会
Sales Activities
客户互动
Follow-up / Tasks
反馈与待办
Dashboard
管理汇总
最简单的理解：Sales Leads 和 Pipeline 说明“我们在跟谁、机会到了哪里”；Sales Activities 说明“我们实际做了什么”；Tasks 说明“下一步还要做什么”。

2. Sales Activities（销售活动）是什么

Sales Activities 用来统一管理销售人员与客户发生的实际互动。它不是普通备注，而是一条有负责人、客户来源、日期、状态和后续动作的业务记录。

2.1 两种活动类型

类型适合记录什么日期规则完成方式
On-site Visit
外勤拜访		到客户办公室、项目现场、活动现场进行面对面会议或勘察。填写开始日期时间和结束日期时间；不再重复填写单独的活动日期。拜访结束后，在 Sales Activities 中填写拜访反馈。
Remote Engagement
远程沟通		邮件、电话、线上会议、即时通讯，以及不需要到现场的客户沟通。使用 Activity Date；如果填写 Next Steps / To-do，还必须填写到期日期。沟通记录可立即完成；待办事项通过关联的 Task 完成。

2.2 一条活动应回答哪些问题

  • 谁负责：Owner。
  • 客户从哪里来：Sales Leads、Pipeline、Existing Customer、Marketing Event 或 Other。
  • 什么时候发生：远程沟通日期，或外勤拜访的开始与结束时间。
  • 联系了谁：联系人、职位和联系方式，可添加多位联系人。
  • 为什么做：Purpose / Project 与 Expected Result。
  • 结果和下一步：Follow-up Notes、Completion Notes、Next Steps / To-do。

3. 如何新建销售活动

1
进入左侧菜单 Sales Activities，点击 Add Sales Activity。
2
选择 On-site Visit 或 Remote Engagement。
3
选择 Source Type，并搜索或填写公司。选择 Sales Leads / Pipeline 时，必须从系统搜索结果中选择，不能只手工输入名称。
4
填写日期、联系人、目的、预期结果和备注。外勤拜访要完整填写开始和结束时间。
5
远程沟通至少填写一项：已完成的 Follow-up Notes，或未来要完成的 Next Steps / To-do。
6
保存后检查 Activity List 和日历。如果创建了待办，系统也会同步生成 Task。

3.1 Source Type 应该怎么选

来源什么时候使用系统关联
Sales Leads客户仍处于潜在客户阶段。必须选择系统中的 Lead；活动和反馈会关联到该 Lead。
Pipeline客户已经是明确的销售机会。必须选择系统中的 Pipeline；活动和反馈会关联到该机会。
Existing Customer与已成交或已开通客户进行续约、维护或新需求沟通。系统会提供 Deal Won / Activated 客户建议，也允许按实际情况填写公司。
Marketing Event展会、研讨会、市场活动中的客户互动。系统会从带 Event 信息的 Leads 中提供建议。
Other不属于以上类型的客户或合作方互动。公司名称可以手工填写。
避免重复客户：如果客户已经存在于 Sales Leads 或 Pipeline，请优先选择对应来源并从搜索结果中选中，这样后续反馈才能正确同步。

4. 状态与提醒

列表中的状态分为“业务状态”和“时间提醒”。因此一条待跟进活动还可能同时显示 Due Today 或 Overdue。

显示代表什么建议动作
Scheduled活动尚未到需要反馈或处理的时间。按计划执行；如客户改期，使用 Edit / Reschedule 修改。
Follow-up Required活动已经到了需要填写反馈或完成下一步的阶段。尽快填写拜访结果，或处理关联 Task。
Due Today远程 To-do 今天到期。它同时属于 Follow-up Required。今天完成并填写完成说明。
Overdue远程 To-do 已过到期日，或外勤拜访结束超过24小时仍未填写反馈。优先处理，并补充真实反馈。
Completed活动已经完成并保存结果。如有下一步，继续建立 To-do。
Cancelled活动取消，取消原因会保留。如需重新安排，建议新建或在取消前改期。

4.1 外勤拜访的时间规则

  • 结束时间之前：Scheduled。
  • 到达结束时间：Follow-up Required。
  • 结束超过24小时仍未反馈：Follow-up Required + Overdue。
  • 填写反馈后：Completed，关联 Task 也会完成。

4.2 为什么统计表没有单独的 Due Today 和 Overdue

在 Activity List 中，它们会作为详细提醒单独显示；但在 Activities by Owner 汇总中，Due Today 和 Overdue 都计入 Follow-up Required。这样可以保证：

Scheduled + Follow-up Required + Completed + Cancelled = Total，每条活动只在业务汇总中计算一次。

5. 日历、筛选与统计

5.1 顶部筛选

  • Type：All、On-site Visit、Remote Engagement。
  • Date Range：远程沟通按 Activity Date 筛选；跨日外勤拜访只要与日期范围有重叠就会被找到。
  • Owner：管理员可按住 Ctrl / Cmd 多选负责人，再点击 Filter；不选择代表 All Owners。
  • 普通用户：不显示 Owner 筛选，只能查看自己的活动。

5.2 日历颜色怎么理解

标识含义
绿色背景该日存在 Scheduled 或 Completed 活动。
黄色背景该日存在 Follow-up Required 或 Due Today。
红色背景该日存在 Overdue 活动。
灰色背景该日活动全部取消，或属于不再需要突出处理的历史日期。
蓝色日期圆圈 + 今天表示今天，不会覆盖原来的状态背景色。
紫色外框表示你点击选中的日历日期，可选择多个日期进行筛选。

5.3 两张汇总表

  • Activities by Owner：按 Scheduled、Follow-up Required、Completed、Cancelled 汇总。普通用户只看到自己，管理员可看到筛选范围内的所有人。
  • Source Type by Owner：按 Sales Leads、Pipeline、Existing Customer、Marketing Event、Other 汇总活动来源。
  • Total：统一放在最后一列，并使用不同背景帮助识别。

5.4 Activity List

活动列表每页显示20条。分页会保留当前的类型、日期、Owner 和日历日期筛选。未完成、未取消的活动可以修改或改期；取消需要填写原因；删除会归档记录及关联 Task，而不是无痕删除。

6. 与其他模块的关系

6.1 Sales Leads（潜在客户）

Sales Leads 用来管理尚未形成明确机会的客户。选择 Sales Leads 作为活动来源后：

  • 只能从你有权限查看的 Lead 中选择。
  • 远程 Follow-up、To-do、外勤拜访计划和拜访反馈会写入 Follow-up History。
  • 如果 Lead 已关联 Pipeline，相关记录会同时同步到对应 Pipeline。

6.2 Pipeline（销售机会）

Pipeline 用来管理已经明确的机会、阶段、金额、预计签约及开通时间。选择 Pipeline 作为活动来源后：

  • 活动会与具体机会关联，便于在沟通记录中保留业务上下文。
  • 完成反馈时可更新 Stuckpoint；界面提供时也可同步调整 Stage。
  • Owner 或 Support 成员只能选择自己有权限的 Pipeline；管理员可选择全部。
  • 如 Pipeline 来源于 Lead，反馈也会同步回该 Lead。

6.3 Existing Customer、Marketing Event 与 Other

这三项主要是活动来源分类：

  • Existing Customer：用于已成交/已开通客户的维护、续约和追加需求。目前它是来源分类，不是单独的客户主数据模块。
  • Marketing Event：用于展会或活动产生的互动，可搜索已有 Event Leads。
  • Other：用于合作伙伴、临时项目或无法归入其他来源的对象。

6.4 Follow-up History（跟进历史）

Follow-up History 是客户和机会上的长期沟通轨迹，主要用于回顾“之前发生过什么”。它与 Sales Activities 的区别是：

Sales ActivitiesFollow-up History
可按Owner、日期、状态和来源统计；可以改期、完成、取消。按时间追加到 Lead / Pipeline，用于查看历史上下文，不作为独立待办。

6.5 Tasks / To-do（待办任务）

  • Remote Engagement 中填写 Next Steps / To-do，会创建一条待处理 Sales Activity 和一个关联 Task。
  • On-site Visit 保存后，也会自动创建一个关联 Task，到期日为拜访结束日期。
  • Remote To-do 应在 Tasks 中完成，并填写 Completion Notes；完成后 Sales Activity 自动同步为 Completed。
  • On-site Visit 必须在 Sales Activities 中填写拜访反馈，系统再同步完成关联 Task。
  • 改期会同步 Task 的日期、Owner 或内容；取消活动会同步取消尚未完成的 Task。

6.6 Dashboard（管理看板）

Dashboard 主要展示 Leads、Pipeline、金额和阶段等整体经营指标。Sales Activities 的执行情况目前以本模块自己的日历、Activities by Owner 和 Source Type by Owner 为主要查看入口。

7. 推荐工作方式

示例一：安排一次外勤拜访

  1. 选择 Sales Leads 或 Pipeline，并从搜索结果中选择客户。
  2. 填写拜访开始/结束时间、地址、联系人、目的和预期结果。
  3. 客户改期时，点击 Edit / Reschedule 修改，关联 Task 会同步。
  4. 拜访结束后及时填写反馈；如果还有动作，创建 Next Steps / To-do。
  5. 不要等到24小时后变成 Overdue 才补记录。

示例二：记录线上会议和下一步

  1. 选择 Remote Engagement。
  2. 在 Follow-up Notes 写清楚已经沟通和确认的内容。
  3. 在 Next Steps / To-do 写清楚下一动作和到期日期，例如“8月7日前发送修订报价”。
  4. 保存后系统会生成一条 Completed 的沟通记录，以及一条 Scheduled 的待办和关联 Task。
  5. 完成任务时填写实际结果，而不是只把状态点成完成。
推荐原则：已发生的沟通写 Follow-up；未来要做的事情写 Next Steps / To-do；需要到客户现场的安排写 On-site Visit。

8. 权限与常见问题

8.1 权限

用户可以看到什么Owner 能力
管理员全部销售活动，可按一个或多个 Owner 筛选。新建或改期时可以指定 Owner。
非管理员只看到自己的活动、日历和汇总。Owner 固定为本人，无法通过 URL 查看其他人的数据。
为什么 Remote To-do 没有 Follow-up 按钮？因为它和 Task 是同一件待办，应在 Tasks 中完成，避免两个地方重复操作造成状态不一致。
客户时间变了怎么办？只要活动还没有 Completed 或 Cancelled，就可以使用 Edit / Reschedule 修改日期、时间、Owner 和相关内容。
跨天拜访会不会被日期筛选漏掉？不会。只要拜访时间段与筛选日期范围有重叠，就会被包含。
Cancel 和 Delete 有什么区别？Cancel 表示业务上取消，活动仍保留并显示取消原因；Delete 表示从正常列表归档，同时归档关联 Task。
为什么普通用户 Activities by Owner 只有一行？因为普通用户只能查看自己的活动；管理员才会看到多个 Owner。
